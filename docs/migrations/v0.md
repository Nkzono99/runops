# v0 Migration Guide
v0 系は pre-public な開発期間です。後方互換 layer を長く維持するよりも、project
ごとに移行手順を明示して素早く設計を改善する方針です。

この guide は `0.x` の runops へ更新するときに確認します。該当しない item は
`not applicable` として扱い、必要なものだけ `migrate-runops` で適用します。

## M0-Ordinary bundle transaction receipt v1

- Type: breaking-recovery-format
- Impact: interrupted `runo runs archive|restore PARENT --bundle`
- What changed:
  - 通常 bundle も move 前に `.runops-bundle-{archive,restore}-*.receipt.toml` v1 を作り、
    root/scaffold、child directory/tree、manifest exact pre/postimage、marker image を固定する。
  - receipt 後の例外は unsafe な自動 rollback を行わず、同じ command の forward recovery にする。
- Migration:
  - 旧版で中断し receipt がない partial bundle は自動推測せず、source/destination と marker を
    手動確認する。新 v1 receipt がある transaction は receipt を削除せず同じ command を再実行する。
- Validation:
  - source parent の receipt と source/destination の一方だけが存在することを確認する。
- Rollback:
  - v1 receipt や live tree に drift がある場合は自動 rollback せず診断用に保持する。

## M0-Bundle adoption receipt v2

- Type: breaking-recovery-format
- Impact: interrupted `runo runs archive PARENT --bundle --adopt-archived`
- What changed:
  - pending adoption receipt が format v2 となり、manifest pre/postimage digest、Run directory
    device/inode、Run tree と source scaffold の identity digest を固定する。
  - receipt 後の manifest/tree drift は transaction を変更せず fail-closed にする。
- Migration:
  - pending v1 receipt は自動変換しない。`runo triage` で source、staging、destination を確認し、
    receipt/staging を削除または移動せず runops の更新版で手動復旧方針を決める。
  - pending transaction がなければ作業は不要。
- Validation:
  - 新規 `receipt.toml` の `adoption.format_version` が `2` で、全 `[[runs]]` に
    `manifest_preimage_sha256`, `manifest_postimage_sha256`, `directory_device`,
    `directory_inode`, `tree_identity_sha256` がある。
- Rollback:
  - v2 receipt を v1 に書き換えない。旧 runops では pending transaction を read-only に保つ。

## M0-Experiment lifecycle and immutable Run identity

- Type: breaking-workflow
- Impact: formal Run creation, smoke/debug, research notes, Result retention
- What changed:
  - formal work is admitted through a bounded Experiment and lazy Survey
    selection; smoke/debug uses `.runops/test-runs/T...` instead of a formal Run.
  - `runs regenerate` is read-only with `--dry-run`; changed inputs require a
    new Run through clone/extend.
  - durable narrative is limited to CURRENT, journal, and one README per Result.
  - sealed Result path evidence blocks destructive `purge-work` of its source.
- Migration:
  - create an Experiment for each currently active bounded question and classify
    existing Runs by `intent`, `curation`, and `storage` as they are next touched.
  - move provisional notes to `.runops/work/`; use `research migrate-legacy` for
    legacy durable notes.
  - run `runo triage --json` before creating additional formal Runs.
- Rollback:
  - existing v0 manifests remain readable; do not rewrite frozen inputs in place.

## 1.0.0 Quantity-bounded Research Workspace

- Type: breaking-project-state
- Impact: research memory, Agent harness, project scaffold
- Applies when:
  - `notes/`, `research/agenda.md`, `analysis/cross_run/`、旧 experiment ledger、
    `.harnessops/` のいずれかを使っている。
- What changed:
  - 現在判断を `research/CURRENT.md`、時系列ログを文字数で rotation する
    `research/journal/`、人が残すと決めた解析を `research/results/` に集約した。
  - 作業中の provisional output は Git 管理外の `.runops/work/<goal-id>/` に置く。
  - `notes`, `experiment`, paper-request の公開 CLI/MCP surface と HarnessOps 依存を撤去した。
- Migration:
  - まず `runo research migrate-legacy /path/to/project --dry-run` で移動一覧を確認する。
  - 内容を確認後、`runo research migrate-legacy /path/to/project` を実行する。
  - 旧内容は `research/archive/legacy/` へそのまま移り、要約・削除されない。
- Validation:
  - `runo research status` と `runo research check` が成功する。
  - active research root が `CURRENT.md`, `journal/`, `results/`, `archive/` に収まる。
  - `.gitignore` が `.runops/work/` を除外する。
- Rollback:
  - `runo research migrate-legacy /path/to/project --restore` で
    `MIGRATION.json` に記録された全パスを元へ戻す。
- Human gate:
  - migration apply 前に dry-run の対象一覧を人が確認する。

## M0-0001 Analysis artifact indexes

- Since: 0.7.0
- Type: compatible-generated
- Impact: analysis-artifact
- Applies when:
  - project に `runs/<run>/analysis/` または `runs/<survey>/summary/` の解析成果物がある。
  - 後続 Agent が figure / CSV / Markdown summary / script の意味を復元しにくい。
- What changed:
  - analysis artifact を一級市民として扱うため、run-local 解析は
    `runs/<run>/analysis/artifacts.toml`、survey / cross-run 集計は
    `runs/<survey>/summary/artifacts.toml` に index を置けるようになった。
  - `kind`, `path`, `title`, `script`, `data`, `description`, `status` を中心に、
    成果物の意味と provenance を軽く記録する。
- Migration:
  - CLI で確認する: `runo migrate apply M0-0001 --dry-run`
  - CLI で適用する: `runo migrate apply M0-0001`
  - 既存の解析成果物はそのまま有効。必須 migration はない。
  - active な run / survey だけ、次回の解析時に `runo analyze summarize` または
    `runo analyze collect` を再実行して `artifacts.toml` を生成する。
  - 既存 `analysis/summary.json` や `summary/survey_summary.*` から index だけを
    補完する場合は、上記 CLI migration を使う。
  - 手作業で index を補う場合は、成果物の隣に置き、相対 path で `path`,
    `script`, `data` を書く。
- Validation:
  - `artifacts.toml` 内の `path` が実在する。
  - note / report から figure や CSV を参照するとき、同じ成果物が
    `artifacts.toml` にも載っている。
  - `runo analyze` 系 command が対象 run / survey で失敗しない。
  - `runo lint --scope analysis` が対象 artifact index の不足を報告しない。
- Rollback:
  - `artifacts.toml` は index なので、削除しても元の解析成果物は失われない。
- Human gate:
  - 不要。大量の古い run に対して一括再解析する場合だけ、人間に scope と cost を確認する。

## M0-0002 Minimal research workspace scaffold

- Since: 0.7.0
- Type: compatible-generated
- Impact: research
- Applies when:
  - project に最小 `research/` scaffold が不足している。
- What changed:
  - `runo context --json` が文字数、active result 数、budget issue を含む
    `research` summary を返す。
- Migration:
  - CLI で確認する: `runo migrate apply M0-0002 --dry-run`
  - CLI で適用する: `runo migrate apply M0-0002`
  - `research/CURRENT.md` や journal がない既存 projectでは
    `runo update-harness --only research` を実行する。
  - `update-harness` を使えない状況で不足分だけ補完する場合は、上記 CLI
    migration を使う。既存 file は上書きしない。
- Validation:
  - `runo context --json` に `research.current_chars`, `journal_chars`,
    `active_result_count`, `issues` が含まれる。
  - `runo lint --scope structure,knowledge` が最小 scaffold と budget を検査できる。
- Rollback:
  - 不要。
- Human gate:
  - `CURRENT.md` の現在判断を大きく書き換える場合だけ、人間に確認する。

## M0-0003 Remove legacy survey figure index

- Since: 0.7.0
- Type: breaking-generated
- Impact: analysis-artifact
- Applies when:
  - project に `runs/<survey>/summary/figures_index.json` がある。
  - `summary/artifacts.toml` に `path = "figures_index.json"` の旧互換 entry がある。
- What changed:
  - `runo analyze collect` は `summary/figures_index.json` を生成しない。
  - figure の索引は `summary/artifacts.toml` を正本にする。
  - `summary/survey_summary.json` には引き続き run ごとの `figures` 情報が入る。
- Migration:
  - CLI で確認する: `runo migrate apply M0-0003 --dry-run`
  - CLI で適用する: `runo migrate apply M0-0003`
  - 既存 `summary/figures_index.json` を削除する。
  - `summary/artifacts.toml` に残っている `figures_index.json` entry を削除する。
- Validation:
  - `runo analyze collect <survey>` を実行しても `summary/figures_index.json` が生成されない。
  - `summary/artifacts.toml` に figure artifact と summary outputs が残っている。
  - `summary/survey_summary.json` の各 run entry に必要な `figures` 情報が残っている。
  - `runo lint --scope analysis` が `analysis.legacy_figures_index` を報告しない。
- Rollback:
  - 旧形式が必要な場合は `summary/survey_summary.json` または `summary/artifacts.toml` から
    project-local script で一時生成する。
- Human gate:
  - 不要。削除対象は runops が生成した legacy index のみ。

## M0-0005 Grouped CLI and internal application boundary

- Since: next v0 release
- Type: breaking-internal / compatible-cli-alias
- Impact: developer imports, scripts, Agent guidance
- Applies when:
  - script や文書が古い flat command (`runops submit`, `runops collect` 等) を使う。
  - project-local Python code が旧 `runops.core.actions`, `runops.core.run_creation`,
    analysis/publication/operator helper を import する。
- What changed:
  - preferred executable は `runo`、現行 surface は grouped command になった。
    例: `runo runs submit`, `runo analyze collect`, `runo runs archive`。
  - 確認省略は `--yes` が canonical。`runo update --force` は同一 semantics の
    **hidden** compatibility alias としてだけ残る。
  - 内部レイヤを `core/ -> application/ -> interfaces/infrastructure` に整理した。
    orchestration は `core/` から `application/` へ移り、MCP tool implementation は
    capability module に分割された。
- Migration:
  - shell script と Agent guidance を `.codex/rules/commands.md` の grouped `runo`
    command に置き換える。
  - internal Python import は次へ更新する。旧 internal path の compatibility shim は
    提供しない。
    - `runops.core.actions` → `runops.application.actions`
    - `runops.core.run_creation` → `runops.application.run_creation`
    - `runops.core.context` → `runops.application.context`
    - `runops.core.analysis` → `runops.application.analysis`
    - `runops.core.publication` → `runops.application.publication`
    - `runops.core.readiness` → `runops.application.execution.readiness`
    - `runops.core.retry` → `runops.application.execution.retry`
    - `runops.core.plugins` → `runops.application.gateway.plugins`
    - `runops.core.lint` → `runops.application.operator.lint`
    - `runops.core.migrations` → `runops.application.operator.migrations`
  - application 境界の移動だけでは manifest/project-state を書き換えない。未知
    manifest field も保持される。ただし、現行 `schemas/manifest.json` に対する
    validation と submit lock の ignore 設定は M0-0006 を確認する。
- Validation:
  - `uv run runo --help` と対象 grouped command の `--help` が成功する。
  - `runo runs submit --dry-run` と MCP submit plan が同じ command/precondition を返す。
  - project の `manifest.toml` bytes/field が internal import 移動だけで変化しない。
- Rollback:
  - code checkout を以前の v0 release に戻す。project-state rollback は不要。
- Human gate:
  - bulk submit など実際の外部操作を validation する場合のみ必要。

## M0-0006 Durable submit lock and strict manifest validation

- Since: next v0 release
- Type: breaking-schema / compatible-runtime
- Impact: existing project `.gitignore`, manifest validator, submission recovery
- Applies when:
  - 既存 project の `.gitignore` に `**/.runops-submit.lock` がない。
  - 以前の `schemas/manifest.json` では valid だった manifest を、現行 schema でも
    validation する。
  - run root に `pending` または `accepted:<job_id>` を含む
    `.runops-submit.lock` がある。
- What changed:
  - submit の process lock と durable claim は run root の
    `.runops-submit.lock` を共有する。この file は lock inode を安定させるため
    submit 完了後も空 file として残る内部 artifact で、Git 管理しない。
  - `schemas/manifest.json` は SPEC 12.3 の required table/field と型を厳密に要求する。
    したがって、旧 schema では valid だった manifest が現行 validator で invalid に
    なることは breaking な schema contract 変更である。
  - runtime の `read_manifest()` は v0 compatibility のため、required data が不足する
    旧 manifest も引き続き読み取る。通常の read/update では未知 field も保持する。
- Migration:
  - まず `runo update-harness --dry-run` で managed `.gitignore` の差分を確認し、
    `runo update-harness` で反映する。手動 merge する場合は project の
    `.gitignore` に次の pattern を追加する。

    ```gitignore
    **/.runops-submit.lock
    ```

  - `.runops-submit.lock` が `pending` または `accepted:<job_id>` を含む場合、scheduler
    の受付結果と `manifest.toml` の `run.status`, `job.job_id`, `job.submitted_at` を
    照合して reconcile する。照合・復旧が完了する前に lock file を unlink、truncate、
    または空文字で上書きしてはならない。空の persistent lock file も通常運用では
    unlink しない。
  - `runo lint --scope runs` を実行し、`runs.manifest_table_missing`,
    `runs.manifest_field_missing`, `runs.manifest_field_type` を確認する。診断された
    manifest は SPEC 12.3 と `schemas/manifest.json` に合わせ、最低限次を補完する。
    - `[run]`: `id`, `status`
    - `[origin]`: `case`
    - `[simulator]`: `name`
    - `[launcher]`: `name`
    - `[simulator_source]`: `resolver_mode`, `source_repo`, `git_commit`,
      `build_command`, `executable`, `exe_hash`, `package_version` を string、
      `git_dirty`, `git_state_observed` を boolean で記録する。取得不能な string は `""`、
      `git_dirty`, `git_state_observed` は `false` で補完する。旧 manifest の
      `git_dirty = false` だけから観測成功を推測してはならず、観測証拠がなければ
      `git_state_observed = false` のままとする。
    - `[job]`: `scheduler`, `job_id`, `submitted_at`
    - `[params_snapshot]`: run 生成時の parameter snapshot。復元できない場合も
      空 table を置き、推測値を作らない。
  - `run.id`, `run.status`, `origin.case`, `simulator.name`, `launcher.name` は、run dir、
    `status/state.json`、元の case、project の simulator/launcher 設定から復元する。
    scheduler 未受付の run では `job_id = ""`, `submitted_at = ""` とし、受付済み
    job の値を空にして schema だけ通すことはしない。
- Validation:
  - `git check-ignore -v --no-index runs/example/.runops-submit.lock` が project の
    `.gitignore` に追加した pattern を表示する。検証のために実 run の lock file を
    作成・変更する必要はない。
  - `runo lint --scope runs` が required table/field/type の issue を報告しない。
  - 利用中の TOML/JSON Schema validator で各 `manifest.toml` が現行
    `schemas/manifest.json` に適合する。
- Rollback:
  - 補完した canonical table/field は以前の v0 release でも TOML data として読める。
    ただし lossless manifest 対応 (`ced2f05`) より前へ戻す場合は unknown top-level
    section と canonical table 内の unknown field を先に backup する。旧版で status
    更新などの manifest rewrite を行うと、それらの extension data は失われ得る。
  - `.gitignore` pattern は残す。claim の有無にかかわらず、rollback 手順として
    `.runops-submit.lock` を一括削除しない。
  - durable claim を認識しない旧版へ戻す前に、全 run の `pending` /
    `accepted:<job_id>` を scheduler と照合して manifest へ reconcile する。未解決の
    claim が一つでもあれば、rollback 後の runtime でもその run を submit しない。
- Human gate:
  - `pending` / `accepted:<job_id>` claim の scheduler 照合と manifest reconcile は
    人間が job identity と受付結果を確認してから行う。

## M0-0007 Bounded Experiment / lazy Survey / isolated TestAttempt

- Since: unreleased
- Type: breaking-cli / compatible-project-default / additive-schema
- Impact: Run creation, Survey expansion, smoke/debug, research notes and Results
- Applies when:
  - `runo runs sweep` が全 candidate directory を一度に作る前提の script / Agent guidance がある。
  - smoke / debug を通常の `RYYYYMMDD-NNNN` Run として保存している。
  - case / survey `notes.md` や Run `analysis/notes.md` に experiment narrative が分散している。
  - Run に global な selected / paper flag を置いて evidence を表している。
  - Result evidence に使う既存 Run manifest が短縮 hash、mixed-case hex、または
    `sha256:` prefix だけの identity / executable hash を持つ。
- What changed:
  - Experiment は `experiments/EYYYYMMDD-NNNN--slug.toml` 一枚で question、baseline、
    finite budget、有効期限、exit criteria、review decision を持つ。
  - `runo runs sweep` の既定動作は lazy / read-only plan となり、directory と Run ID を
    作らない。materialize には `--apply`、`--point` または `--all`、preview の
    `--expect-plan` が必要になった。
  - 新規 scaffold は `[experiments.policy] require_experiment = true`。section のない既存
    project は互換性のため `false` として読み、更新だけで既存 Run 作成を突然 block しない。
  - smoke / debug は `.runops/test-runs/T.../test-receipt.toml` へ分離した。完全な identity の
    passed cache hit は既存 attempt を返し、新しい T ID / directory / receipt を作らない。
    record/cache reuse は input 実体を再ハッシュする。cleanup receipt v2 は directory identity、
    tree entry fingerprint と tree/receipt/input digest を固定し、部分削除後も変更されていない
    survivor のみ再開する。v1 pending receipt は自動削除へ進めない。
  - Run manifest に intent、identity、curation、storage metadata を追加した。lifecycle、
    review、storage tier/form、Result evidence selection は直交する。
  - canonical Result は claim-local evidence edge と seal receipt を持つ。T ID と
    `.runops/test-runs/**` は scientific evidence として拒否される。included Run / Run-owned
    artifact は completed 相当、理由付き review、identity / source / baseline / input snapshot
    の quality gate を通す。
  - Result seal に使う `condition_hash`, `input_hash`, `execution_hash`,
    `provenance_hash` と simulator executable hash は、正規の
    `sha256:<64 lowercase hex>` だけを受理する。manifest schema も、値が存在する
    identity hash について同じ正規形を要求する。
  - `runo lint` は case / survey `notes.md` と Run `analysis/notes.md` を legacy dispersed
    narrative として warning にする。
  - project の未 review completed Run 上限は `require_experiment` と独立し、未所属 Run の
    create / Survey materialization / clone / extend / retry にも適用する。
  - formal Run target は strict discovery が prune する `.tmp-*` / `.delete-*` 配下と、既存
    `manifest.toml` を持つ Run の子孫を拒否する。
  - `job.walltime` は全 formal Run 経路で正の `H+:MM:SS` / `D-H+:MM:SS` に統一し、
    minute / second の範囲外、負値、ゼロ時間を拒否する。
- Migration:
  1. Agent / shell guidance の `runo runs sweep <dir>` を、まず read-only preview として扱う。
     旧「全生成」は機械的に `--all` へ置換せず、point と budget を人が確認する。
  2. 継続する研究上の問いごとに `runo experiments create` を使い、baseline または
     baseline 不要理由、全 budget、UTC offset 付きの未来の `budget.expires_at`、exit criteria
     を記録する。既存の Experiment TOML に `expires_at` がない場合は schema/core validation
     で unreadable になるため、formal Run 操作の前に期限を明示して移行する。
  3. formal `survey.toml` に explicit `survey.id`, `experiment_id`, `phase`,
     `[intent].purpose`、必要なら `[budget]` / `[retention]` を追加する。
  4. `runo runs sweep <dir>` の preview から point ref と plan hash を取得し、例えば
     `runo runs sweep <dir> --apply --point p0001 --expect-plan sha256:...` とする。
  5. 新規 policy を既存 project に適用する準備ができたら、`runops.toml` に次を追加する。

     ```toml
     [experiments.policy]
     require_experiment = true
     max_active_experiments = 5
     default_max_materialized_runs = 3
     max_unreviewed_completed_runs = 12
     ```

  6. smoke / debug workflow は `runo test smoke|debug` と `runo test record` へ移す。既存の
     R Run は自動で T ID に変換・削除せず、必要なら terminal review / archive を行う。
  7. `runo research migrate-legacy --dry-run` と `runo lint --scope knowledge` で分散 note を
     確認する。provisional prose は `.runops/work/`、時系列は journal、current decision は
     CURRENT、残す narrative は一つの Result README へ手動で整理する。
  8. 残す claim は `runo research new-result`、`seal --evidence-run|--evidence-path` へ移す。
     旧 Result / comparison layout は read-only のまま保持できるが canonical seal はしない。
  9. managed project の既存 automation が `runs/_archive` 外へ `--move-to` している場合は、
     archive root を同一 filesystem の `runs/_archive/**` 内へ変更する。外部保管は runops の
     lifecycle 操作ではなく、別途 export/backup として扱う。
  10. 既存 Run を Result evidence にする前に identity と executable provenance を検査する。
      短縮値、uppercase、non-hex 値は元の input snapshot、execution config、source / binary
      から再計算する。正しい原本がなければ hash を捏造せず、その Run は seal 対象から外して
      provenance 不足を明記する。
  11. 既存の `curation.review_status = "reviewed"` は、timezone-aware ISO-8601
      `reviewed_at`、non-empty な `reviewed_by` と `reason` が揃っているか確認する。不完全な
      record は未 review backlog として扱われ、必要なら `runo runs review --reason ...` で
      terminal Run を改めて review する。
  12. 既存 Case / Survey / Run manifest の `job.walltime` を検査する。`120:00:00` や
      `5-00:00:00` はそのまま使えるが、`00:00:00`、負値、minute / second が 60 以上の値は
      実際に投入する正の上限へ修正してから clone / extend / retry する。
  13. `.tmp-*` / `.delete-*` 配下または Run directory 内に手動配置した formal Run / Survey は、
      active `runs/` tree の可視な親へ移し、Run ID と manifest の一意性を確認する。
- Validation:
  - `runo experiments list` に active Experiment が表示される。
  - `runo runs sweep <dir>` の出力が `0 directories created` と plan hash を示し、filesystem と
    Run sequence が変わらない。
  - selected apply が budget 内の点だけを作り、同じ apply の再実行は existing Run を reuse する。
  - `runo test list` と `runo runs list` が別 namespace を表示し、cache hit 前後で
    `.runops/test-runs/` の directory 数が増えない。
  - `runo research check-result RESULT` が seal receipt を検証し、T ID evidence を拒否する。
  - seal 対象 Run の上記 5 種類の hash がすべて `sha256:` に続く 64 文字の lowercase hex
    であり、短縮値や mixed-case 値では quality gate が失敗する。
  - `runo lint --scope knowledge` で残った legacy note slot を確認できる。
  - Experiment 未所属の completed Run backlog が上限に達した状態で、ownerless create / sweep /
    clone / extend / retry が同じ project-wide diagnostic で拒否される。
  - `job.walltime = "00:00:00"` を持つ Case / Survey / managed derived Run が materialize されない。
- Rollback:
  - `require_experiment = false` を明示すれば旧 project の standalone Run gate を緩められる。
    ただし project-wide 未 review backlog gate は無効にならない。必要なら completed Run を
    review するか、policy 上限を意図的に見直す。
    Experiment / intent / identity / curation / storage field は旧版で unknown metadata として
    残せるが、unknown-field preservation 対応より古い版で manifest を rewrite しない。
  - 新方式で materialize 済みの Run を旧 sweep で再生成しない。`point_id` idempotency を
    認識しない旧版は duplicate directory を作り得る。
  - TestAttempt と sealed Result は旧版が管理しないため、内容を消さず read-only に保つ。
  - 旧版へ戻しても canonical hash を短縮値へ戻さない。再計算できない legacy Run は
    unsealed / read-only のまま保持し、品質 gate を迂回して Result を作らない。
- Human gate:
  - Experiment budget、`decision=expand`、`--all` materialization、旧 note から durable Result
    への evidence selection は人が確認する。
