# v0 Migration Guide

v0 系は pre-public な開発期間です。後方互換 layer を長く維持するよりも、project
ごとに移行手順を明示して素早く設計を改善する方針です。

この guide は `0.x` の runops へ更新するときに確認します。該当しない item は
`not applicable` として扱い、必要なものだけ `migrate-runops` で適用します。

## M0-0001 Analysis artifact indexes

- Since: 0.7.0
- Type: compatible-generated
- Impact: analysis-artifact
- Applies when:
  - project に `runs/<run>/analysis/` または `runs/<survey>/summary/` の解析成果物がある。
  - 後続 Agent が figure / CSV / Markdown summary / script の意味を復元しにくい。
- What changed:
  - analysis artifact を一級市民として扱うため、run-local 解析は
    `runs/<run>/analysis/artifacts.toml`、survey / cross-run 集計は
    `runs/<survey>/summary/artifacts.toml` に index を置けるようになった。
  - `kind`, `path`, `title`, `script`, `data`, `description`, `status` を中心に、
    成果物の意味と provenance を軽く記録する。
- Migration:
  - 既存の解析成果物はそのまま有効。必須 migration はない。
  - active な run / survey だけ、次回の解析時に `runo analyze summarize` または
    `runo analyze collect` を再実行して `artifacts.toml` を生成する。
  - 手作業で index を補う場合は、成果物の隣に置き、相対 path で `path`,
    `script`, `data` を書く。
- Validation:
  - `artifacts.toml` 内の `path` が実在する。
  - note / report から figure や CSV を参照するとき、同じ成果物が
    `artifacts.toml` にも載っている。
  - `runo analyze` 系 command が対象 run / survey で失敗しない。
- Rollback:
  - `artifacts.toml` は index なので、削除しても元の解析成果物は失われない。
- Human gate:
  - 不要。大量の古い run に対して一括再解析する場合だけ、人間に scope と cost を確認する。

## M0-0002 Research agenda in context

- Since: 0.7.0
- Type: compatible-generated
- Impact: research
- Applies when:
  - project に `research/agenda.md` がある、または `runo update-harness` で
    `research/` scaffold が補完される。
- What changed:
  - `runo context --json` が `research_agenda` summary を返し、Agent が最初に
    `research/agenda.md` の存在と現在判断の preview に気づけるようになった。
- Migration:
  - 必須 migration はない。
  - `research/agenda.md` がない既存 project では `runo update-harness` を実行し、
    scaffold された agenda を現在の研究判断に合わせて編集する。
- Validation:
  - `runo context --json` に `research_agenda.exists`, `path`,
    `current_decision_heading`, `next_actions_count` が含まれる。
  - `research/agenda.md` が TODO list ではなく mutable decision ledger として書かれている。
- Rollback:
  - 不要。
- Human gate:
  - agenda の現在判断を大きく書き換える場合だけ、人間に確認する。
